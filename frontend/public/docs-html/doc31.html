📧 Relatório Semanal — Visão Geral

Toda manhã de domingo às 8h BRT, o app envia automaticamente um e-mail HTML com o resumo da carteira para cada usuário que ativou a flag email_relatorios_ativo em /configuracoes.

O que vai no e-mail

  • Patrimônio total (soma de total_value de todos os ativos)
  • Variação % vs aporte total (lucro/prejuízo acumulado, com cor verde/vermelho)
  • Total investido e número de ativos em cards
  • Distribuição por classe (Renda Fixa, Renda Variável, FIIs, Internacional) ordenada por valor
  • Contagem de alertas ≥5% disparados nos últimos 7 dias
  • Botão "Abrir Dashboard" com link direto para NEXT_PUBLIC_APP_URL/dashboard
Sem custo: Resend free tier (100 e-mails/dia, 3000/mês) + Vercel Hobby cron (1 cron/dia, suficiente para semanal). Sem servidor extra, sem cartão de crédito.
Limitação v1: a variação % é vs aporte total, não vs semana anterior — porque o projeto não armazena snapshots históricos diários. Para variação real semana-a-semana seria necessário criar uma tabela de snapshots e popular via cron diário.

🏗️ Arquitetura

Vercel Cron (domingo 11h UTC = 8h BRT) ↓ GET /api/cron/weekly-report • Authorization: Bearer ${CRON_SECRET} ↓ Route Handler (Next.js App Router, runtime nodejs) ↓ Supabase Service Role • SELECT profiles WHERE email_relatorios_ativo = true • Para cada usuário: ─ Skip se ultimo_envio < 6 dias atrás ─ SELECT portfolio_assets (calcula totais + por classe) ─ SELECT count(alertas_variacao) últimos 7 dias ─ Renderiza HTML ─ Resend.emails.send() ─ UPDATE email_relatorios_ultimo_envio = now()

🗄️ Banco de Dados

Migration (sql/email_relatorios_setup.sql)

ALTER TABLE public.profiles
  ADD COLUMN IF NOT EXISTS email_relatorios_ativo BOOLEAN NOT NULL DEFAULT FALSE,
  ADD COLUMN IF NOT EXISTS email_relatorios_ultimo_envio TIMESTAMPTZ;

CREATE INDEX IF NOT EXISTS profiles_email_relatorios_ativo_idx
  ON public.profiles (email_relatorios_ativo)
  WHERE email_relatorios_ativo = TRUE;
  • email_relatorios_ativo — opt-in explícito (default FALSE para LGPD)
  • email_relatorios_ultimo_envio — guarda timestamp do último envio bem-sucedido
  • Índice parcial (WHERE email_relatorios_ativo = TRUE) — o cron lê só usuários ativos, então o índice cobre exatamente esse padrão

⚙️ Route Handler — /api/cron/weekly-report

Auth

const auth = req.headers.get('authorization');
const expected = `Bearer ${process.env.CRON_SECRET}`;
if (!process.env.CRON_SECRET || auth !== expected) {
  return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });
}

Vercel Cron envia automaticamente o header Authorization: Bearer ${'$'}{CRON_SECRET} quando a env var existe no projeto. Sem o secret correto, retorna 401 — bloqueia chamadas externas não autorizadas.

Idempotência (janela de 6 dias)

const SIX_DAYS_MS = 6 * 24 * 60 * 60 * 1000;

if (
  u.email_relatorios_ultimo_envio &&
  now - new Date(u.email_relatorios_ultimo_envio).getTime() < SIX_DAYS_MS
) {
  skipped++;
  continue;
}

Se o cron rodar duas vezes acidentalmente (botão "Run" manual + cron real, por exemplo), a segunda execução pula o usuário em vez de mandar e-mail duplicado.

Cálculo do resumo

let totalInvestido = 0;
let totalAtual = 0;
const porClasseMap = new Map<string, number>();

for (const a of list) {
  const isFixedIncome = a.type === 'renda_fixa';
  const investido = isFixedIncome
    ? Number(a.quantity)              // renda fixa: quantity = R$ aplicado
    : Number(a.quantity) * Number(a.average_price);
  const atual = Number(a.total_value) || investido;

  totalInvestido += investido;
  totalAtual += atual;
  porClasseMap.set(a.type, (porClasseMap.get(a.type) ?? 0) + atual);
}

const variacaoPct = totalInvestido > 0
  ? ((totalAtual - totalInvestido) / totalInvestido) * 100
  : 0;

Lazy init do supabase-admin (evita quebra no build)

O cliente Supabase admin não pode ser instanciado no topo do módulo, porque o Next.js importa todos os route handlers no build — se SUPABASE_SERVICE_ROLE_KEY não estiver definida no momento do build, o throw quebra o deploy.

let cached: SupabaseClient | null = null;

export function getSupabaseAdmin(): SupabaseClient {
  if (cached) return cached;
  const url = process.env.NEXT_PUBLIC_SUPABASE_URL;
  const serviceKey = process.env.SUPABASE_SERVICE_ROLE_KEY;
  if (!url || !serviceKey) throw new Error('vars não definidas');
  cached = createClient(url, serviceKey, { auth: { autoRefreshToken: false, persistSession: false } });
  return cached;
}

🎨 Template HTML

O template em lib/email-templates/weekly-report.ts exporta uma função pura generateWeeklyReportHtml(data) que retorna string HTML. Decisões:

  • Inline styles em todos os elementos — clientes de e-mail (Gmail, Outlook) ignoram CSS em <style> ou removem classes
  • Tabelas para layout (não flexbox/grid) — única forma de layout que funciona em Outlook clássico
  • Sem JavaScript, sem fonts externas — usa -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif para tipografia nativa
  • Escape HTML em nome com função escapeHtml() para evitar quebra de layout (e XSS) caso o usuário tenha tag no nome
  • Cores condicionais — variação positiva verde, negativa vermelho; banner de alertas amarelo se > 0, cinza se 0
  • Responsivo via max-width: 600px — padrão de e-mail; telas pequenas exibem o conteúdo com padding

🌐 Deploy Vercel — Projeto Frontend

O frontend Next.js está hospedado em nuvary-invest.vercel.app. O backend Express continua em projeto Vercel separado (nuvary-invest-backend.vercel.app) — ver doc21 para o setup do backend serverless.

⚠️ Por que o Root Directory importa para o cron: quando esse setting está como frontend, o Vercel lê frontend/vercel.json, não o vercel.json da raiz do repo. Por isso o arquivo de config do cron tem que estar dentro de frontend/.

📁 frontend/vercel.json

Arquivo único e enxuto — apenas declara o framework e o cron. Build/install commands são auto-detectados pelo Vercel.

{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "framework": "nextjs",
  "crons": [
    {
      "path": "/api/cron/weekly-report",
      "schedule": "0 11 * * 0"
    }
  ]
}

🔑 Environment Variables

Configuradas em Vercel Project → Settings → Environment Variables (ambiente Production e, opcionalmente, Preview).

VariávelNecessária paraOnde obter
NEXT_PUBLIC_SUPABASE_URL App + cron Supabase → Project Settings → API → Project URL
NEXT_PUBLIC_SUPABASE_ANON_KEY App (cliente) Supabase → Project Settings → API → publishable key (sb_publishable_...)
SUPABASE_SERVICE_ROLE_KEY Cron (bypassa RLS) Supabase → Settings → API Keys → secret key (sb_secret_...) — NUNCA expor no client
RESEND_API_KEY Cron (envio) resend.com → API Keys (re_...)
CRON_SECRET Cron (auth) Gerar via openssl rand -hex 32 — qualquer string longa aleatória
NEXT_PUBLIC_APP_URL Botão "Abrir Dashboard" do e-mail URL do app (ex: https://nuvary-invest.vercel.app) — opcional, fallback hardcoded para essa URL
EMAIL_FROM Sender do e-mail Opcional — default Nuvary Invest <onboarding@resend.dev> (só envia para e-mails da conta Resend até verificar domínio)
NEXT_PUBLIC_API_URL App (chamadas ao backend Express) URL do projeto Vercel do backend (ex: https://nuvary-invest-backend.vercel.app/api)
🚨 Nunca cole secrets em chat, PR, issue ou commit. Se uma key vazar (foi colada em qualquer lugar visível), rotacione imediatamente: delete a key no painel do provedor, crie nova, atualize a env var no Vercel, redeploy.

⏰ Cron Jobs no Painel

Após o deploy, o cron fica visível em Vercel Project → Settings → Cron Jobs:

/api/cron/weekly-report   0 11 * * 0   At 11:00 AM, only on Sunday
                                         [Run]  [View Logs]

Botão "Run" — disparo manual

  • Útil para testar sem esperar até domingo
  • Vercel chama o endpoint com o CRON_SECRET automaticamente
  • Cuidado com idempotência: se o último envio foi há < 6 dias, retorna skipped: 1 e nenhum e-mail sai. Para forçar re-envio:
UPDATE profiles SET email_relatorios_ultimo_envio = NULL
WHERE email = 'investnet123@gmail.com';

Botão "View Logs"

Mostra todos os requests ao endpoint, com status code e timestamp. Para ver o response body e console.log(), clique numa linha individual.

Disparo manual via curl (alternativa ao botão Run)

curl -i -H "Authorization: Bearer SEU_CRON_SECRET" \
  https://nuvary-invest.vercel.app/api/cron/weekly-report

🩺 Troubleshooting — Lições Aprendidas

"Get Started with Cron Jobs" aparece mesmo após deploy

Significa que a Vercel não detectou o crons no vercel.json. Causa quase certa: o arquivo está na raiz do repo mas o Root Directory está configurado como frontend. Mover para frontend/vercel.json resolve.

Build falha com erro do supabase-admin

Sintoma: deploy fica vermelho com mensagem sobre SUPABASE_SERVICE_ROLE_KEY. Causa: o módulo lança exceção no momento do import. Solução: lazy init (ver seção Route Handler acima).

Cron retorna 200 mas e-mail não chega

Quase sempre é a idempotência de 6 dias. Verifique o response body — se aparecer skipped: 1, é isso. Limpe o email_relatorios_ultimo_envio no Supabase.

Botão "Abrir Dashboard" do e-mail leva a 404

O fallback no código aponta para https://nuvary-invest.vercel.app. Se seu app está em outro domínio, defina NEXT_PUBLIC_APP_URL no Vercel para a URL correta.

Resend retorna erro "to address must be from your verified domain"

Resend free tier com sender padrão onboarding@resend.dev só envia para e-mails da conta dona da API key. Para enviar para qualquer e-mail, verifique um domínio em Resend → Domains e troque EMAIL_FROM para algo como relatorios@seu-dominio.com.

Setup manual (uma vez por projeto):
  1. Rodar sql/email_relatorios_setup.sql no Supabase SQL Editor
  2. Criar conta gratuita no resend.com e gerar API key
  3. Adicionar as 4 env vars novas no Vercel (CRON_SECRET, RESEND_API_KEY, SUPABASE_SERVICE_ROLE_KEY, NEXT_PUBLIC_APP_URL)
  4. Redeploy → cron fica visível em Cron Jobs
  5. Toggle "Relatórios semanais" em /configuracoes para ativar para o usuário
