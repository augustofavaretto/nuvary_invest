🔔 Alertas de Variação — Visão Geral

Sistema completo que dispara notificações quando um ativo da carteira varia ≥ 5% (positiva ou negativa) em relação ao preço médio de compra. Implementado 100% client-side via Supabase, seguindo o padrão arquitetural do projeto (sem rotas no backend Express).

Componentes do sistema

  • Tabela alertas_variacao no Supabase (com RLS por auth.uid())
  • Coluna profiles.alertas_variacao_enabled — toggle do usuário
  • alertasService.ts — CRUD + verificação de variação
  • NotificationBell.tsx — sino com badge e dropdown no header
  • AlertItem.tsx — item visual de alerta (subiu/caiu)
  • AlertToastContainer.tsx — toast em tempo real (8s, canto inferior direito)
  • Toggle em /configuracoes — habilita/desabilita alertas
  • Realtime via Supabase — atualização instantânea + polling 30s + custom event
Threshold: 5% (constante ALERT_THRESHOLD) — Variação calculada como ((currentPrice - averagePrice) / averagePrice) × 100
Anti-spam: mesmo ticker + mesma direção (up/down) é bloqueado por 24h após primeiro alerta. Garantido pelo hasRecentAlert() antes do INSERT.

🗄️ Banco de Dados

SQL completo (sql/alertas_variacao.sql)

-- 1. Tabela principal
CREATE TABLE IF NOT EXISTS alertas_variacao (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE NOT NULL,
  ticker VARCHAR(20) NOT NULL,
  asset_name VARCHAR(100) NOT NULL,
  asset_type VARCHAR(30) NOT NULL,
  direction VARCHAR(10) NOT NULL CHECK (direction IN ('up', 'down')),
  variation_pct NUMERIC(14,2) NOT NULL,
  previous_price NUMERIC(20,8) NOT NULL,
  current_price NUMERIC(20,8) NOT NULL,
  read BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2. RLS
ALTER TABLE alertas_variacao ENABLE ROW LEVEL SECURITY;

-- 3. 4 policies (SELECT, INSERT, UPDATE, DELETE) por auth.uid()
-- 4. 3 índices para performance
CREATE INDEX idx_alertas_user_id ON alertas_variacao(user_id);
CREATE INDEX idx_alertas_created ON alertas_variacao(created_at DESC);
CREATE INDEX idx_alertas_user_ticker_dir
  ON alertas_variacao(user_id, ticker, direction, created_at DESC);

-- 5. Coluna em profiles
ALTER TABLE profiles
  ADD COLUMN IF NOT EXISTS alertas_variacao_enabled BOOLEAN DEFAULT TRUE;

-- 6. Realtime
ALTER PUBLICATION supabase_realtime ADD TABLE alertas_variacao;
ALTER TABLE alertas_variacao REPLICA IDENTITY FULL;

Razão dos tipos numéricos

  • variation_pct NUMERIC(14,2) — suporta variações de até 999.999.999.999,99% (cripto adicionada com preço médio R$1 e atual R$600.000 = 60M%)
  • previous_price NUMERIC(20,8) — 8 casas decimais para criptos como SHIB, DOGE, etc.
  • current_price NUMERIC(20,8) — mesmo motivo

🔄 Fluxo Completo

  1. Usuário clica Atualizar em /carteira ou abre o Dashboard
  2. refreshAllPrices() em portfolioService.ts atualiza current_price no banco para cada ativo de mercado (renda variável, FIIs, internacional, cripto)
  3. No final, dynamic-import de checkAlertsForAssets() e chamada com a lista atualizada
  4. checkAlertsForAssets() verifica alertas_variacao_enabled em profiles — se desabilitado, retorna
  5. Para cada ativo, calcula variação. Se |variação| ≥ 5% e não há alerta recente (24h) → INSERT no Supabase
  6. Variação é truncada em 999.999,99% via MAX_VARIATION_PCT para garantir cabimento na coluna
  7. Após INSERT bem-sucedido, dispara CustomEvent('nuvary:new-alert') no window
  8. NotificationBell escuta o evento → recarrega lista e contagem; AlertToastContainer escuta e renderiza toast 8s
  9. Em paralelo, Realtime do Supabase dispara postgres_changes em qualquer aba aberta → atualiza sino sem refresh

Cap de segurança

const MAX_VARIATION_PCT = 999999.99;

const variation = Math.sign(rawVariation) *
  Math.min(Math.abs(rawVariation), MAX_VARIATION_PCT);

Se um usuário cadastrar BTC com preço médio R$1, a variação real seria ~60.000.000% — recortada para 999.999,99% preservando o sinal.

🧩 Componentes Frontend

NotificationBell.tsx

Substitui o sino estático no DashboardLayout. Contém:

  • Ícone Bell com badge vermelho mostrando contagem de não lidos (9+ se >9)
  • Dropdown com lista dos últimos 20 alertas
  • Botão "Marcar todas como lidas" (aparece se há não lidos)
  • Botão "Ver carteira" no rodapé do dropdown
  • Empty state com ícone e texto orientativo

3 fontes de atualização (defesa em profundidade)

  1. CustomEvent NEW_ALERT_EVENT — disparado pelo checkAlertsForAssets na mesma sessão (instantâneo)
  2. Realtime WebSocket — supabase.channel('alertas-variacao-changes').on('postgres_changes', ...) — atualiza entre abas e dispositivos
  3. Polling 30s — fallback caso Realtime não esteja habilitado
  4. Refresh ao abrir dropdown — garante consistência se outra aba marcou lido

AlertItem.tsx

Cores dinâmicas por direção:

  • up → ícone ArrowUpRight, fundo bg-emerald-500/15, texto text-emerald-400, emoji 📈
  • down → ícone ArrowDownRight, fundo bg-red-500/15, texto text-red-400, emoji 📉

Helper timeAgo() formata: "agora", "há 5m", "há 2h", "há 3d".

AlertToastContainer.tsx

Posicionado fixed bottom-6 right-6 z-50. Escuta o mesmo NEW_ALERT_EVENT. Cada toast:

  • Card escuro bg-[#0B1F33] com ícone, título e preço
  • Auto-dismiss em 8 segundos (TOAST_TTL)
  • Clicável → fecha e leva para /carteira
  • Botão X para fechar manualmente
  • Animação Framer Motion: entra do x:40 + scale:0.95

Toggle em /configuracoes

Card "Alertas de variação" com TrendingUp verde. Persiste via setAlertsEnabled() em profiles.alertas_variacao_enabled. Carregado no mount via getAlertsEnabled().

📡 Habilitando Realtime no Supabase

Via UI (caminho recomendado)

  1. Painel do Supabase → Database → Publications
  2. Encontre supabase_realtime
  3. Clique em "0 tables" à direita da linha
  4. Marque alertas_variacao

Via SQL Editor (mais rápido)

ALTER PUBLICATION supabase_realtime ADD TABLE alertas_variacao;
ALTER TABLE alertas_variacao REPLICA IDENTITY FULL;

Verificação

SELECT tablename FROM pg_publication_tables
WHERE pubname = 'supabase_realtime';
-- alertas_variacao deve aparecer na lista
Diagnóstico no console: com a sessão aberta, os logs [NotificationBell] mostram status do Realtime (SUBSCRIBED, CHANNEL_ERROR, TIMED_OUT) e atualizações de refresh().

🎓 Trilhas Educativas — Player Inline e Progresso

O que mudou

  • Player de vídeo inline — substituiu modal "Em breve" por iframe YouTube embed responsivo (16:9 via paddingBottom: 56.25%)
  • URLs reais por card — campo videoUrl em VideoCard, helper getYouTubeId() com regex /[?&]v=([^&]+)/
  • Removidas categorias cripto e analise (todos os vídeos eram URL de canal, não de vídeo específico)
  • Removido vídeo rv3 "Dividendos" (privado no YouTube)

Recurso "Concluído"

Estado watchedList: Set<string> em TrilhasPage. Cada card recebe a prop watched e renderiza:

  • Thumbnail com filtro brightness-75 quando assistido
  • Badge verde "Concluído" top-left no thumbnail
  • Hover overlay muda texto de "Assistir" → "Rever"
  • Título em text-muted-foreground em vez de text-foreground
  • Botão full-width "Marcar concluído" abaixo das infos do card — toggle, fica verde quando ativo
  • Botão "Concluído / Desmarcar" no rodapé do modal do player — marca + fecha em um clique

Cada slide do hero tem agora um campo category. O botão CTA chama scrollToCategory(slide.category):
