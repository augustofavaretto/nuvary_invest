📝 Chat IA — Markdown renderizado (commit 038a19c)

Respostas da IA retornavam texto com markdown (**negrito**, listas numeradas, etc.) mas eram renderizadas como string crua — o usuario via os asteriscos literais (**Diversificação Internacional** em vez de negrito real).

Solucao

Em src/components/chat/ChatMessage.tsx, respostas do assistente (role === 'assistant') passam por ReactMarkdown com remark-gfm. Mensagens do usuario continuam como texto puro (whitespace-pre-wrap) — sem custo desnecessario de parser.

<ReactMarkdown
  remarkPlugins={[remarkGfm]}
  components={{
    p: ({ children }) => <p className="mb-2 last:mb-0">{children}</p>,
    strong: ({ children }) => <strong className="font-semibold">{children}</strong>,
    ul: ({ children }) => <ul className="list-disc list-outside ml-5 my-2 space-y-1">{children}</ul>,
    ol: ({ children }) => <ol className="list-decimal list-outside ml-5 my-2 space-y-1">{children}</ol>,
    a: ({ children, href }) => <a href={href} target="_blank" className="text-[#00B8D9] hover:underline">{children}</a>,
    code: ({ children }) => <code className="px-1.5 py-0.5 rounded bg-muted text-xs font-mono">{children}</code>,
    h1/h2/h3: ...
  }}
>

As dependencias react-markdown@^10 e remark-gfm@^4 ja estavam no package.json — nao foi necessario instalar nada.

Clicar so preenche o input (nao envia)

📋 Chat IA — Sidebar de conversas (commits 2f2f7ea, 2e14a5d, 3e68b1f)

Botao "tres pontos" sempre visivel

Antes, o botao MoreVertical em cada conversa tinha opacity: 0 ate o hover — em mobile/touch ficava literalmente invisivel. Agora:

.conversa-dots-btn {
  opacity: 1;
  transition: background-color 150ms ease, color 150ms ease;
}

Mesmo padrao do Claude Chat: icone visivel sempre, mudando de cor + bg no hover/focus.

Conserto do truncate dos titulos

Sintoma: titulos das conversas apareciam "deslocados" mostrando so o fim do texto ("...atual e me forneca insights" em vez de "Analise minha carteira atu...").

Causa: o Viewport interno do Radix ScrollArea (shadcn) usa display: table por padrao, o que quebra flex-1 min-w-0 truncate dos filhos.

Fix em globals.css:

[data-slot="scroll-area-viewport"] > div {
  display: block !important;
}

Mais overflow-hidden no item da conversa como defesa em profundidade.

Menu de opcoes simplificado

O dropdown que abre ao clicar nos tres pontos tinha 3 opcoes: Favoritar / Mudar o nome / Apagar. A opcao Favoritar foi removida (era placeholder sem implementacao real — handler so fechava o menu).

Menu atual:

  • ✏️ Mudar o nome — edita inline com Enter/Escape
  • 🗑️ Apagar (vermelho) — abre modal de confirmacao

MENU_HEIGHT ajustada de 132px (3 itens) para 92px (2 itens) — o calculo de reposicionamento na borda inferior do viewport agora considera a altura real.

🪪 CPF nos PDFs fiscais (commit 3bea524)

Antes, ambos os PDFs (DARF e Informe de Rendimentos) exibiam o placeholder ___.___.___-__ no campo CPF, mesmo quando o usuario tinha CPF salvo na tabela profiles.

Solucao

Helper local nas duas funcoes geradoras (gerarDARF() e gerarInformeRendimentos()):

const cpfLimpo = (profile?.cpf || '').replace(/\D/g, '');
const cpfFormatado = cpfLimpo.length === 11
  ? cpfLimpo.replace(/^(\d{3})(\d{3})(\d{3})(\d{2})$/, '$1.$2.$3-$4')
  : '___.___.___-__';

Aceita CPF salvo como "12345678900" ou "123.456.789-00"; sanitiza com \D e aplica a mascara XXX.XXX.XXX-XX. Fallback para placeholder se o usuario nao informou CPF.

Interface Profile expandida

No AuthContext.tsx, a interface Profile ganhou os campos:

interface Profile {
  id: string;
  nome: string;
  email: string;
  aceite_termos: boolean;
  avatar_url?: string;
  cpf?: string | null;            // NOVO
  data_nascimento?: string | null; // NOVO
  telefone?: string | null;        // NOVO
}

Os campos ja eram preenchidos no fetchProfile desde sempre — so faltava declarados no TypeScript.
