💼 AddAssetModal — 3 Refinamentos

1. Símbolo R$ no lugar do ícone $

Os campos de moeda exibiam o ícone genérico DollarSign da lucide-react (símbolo $), o que confundia em uma plataforma 100% BRL. Agora aparece o texto R$ como prefixo nos inputs.

  • Campo "Valor Investido" (renda fixa) — span com texto "R$"
  • Campo "Preço Médio" (renda variável, FIIs, internacional, cripto) — idem
  • Import de DollarSign removido do AddAssetModal.tsx

2. Preço médio bloqueado quando vem da API

O preço de mercado é buscado automaticamente em fetchAssetPrice() ao selecionar o ativo (Brapi, Finnhub, Alpha Vantage). Antes, o usuário podia sobrescrever esse valor manualmente — o que gerava inconsistência entre o preço médio salvo e a realidade da API.

const priceLocked = !isFixedIncome && !isCustom && !!priceInfo?.price;
const isDisabled = priceLoading || priceLocked;

<input
  type="number"
  value={formData.averagePrice || ''}
  disabled={isDisabled}
  readOnly={priceLocked}
  title={priceLocked ? 'Preço de mercado obtido automaticamente — não editável' : undefined}
  className={`... ${isDisabled ? 'bg-muted cursor-not-allowed' : ''}`}
/>
CenárioEditável?
Renda variável / FIIs / Internacional / Cripto com preço da API❌ Bloqueado (read-only, fundo cinza, cursor not-allowed)
Renda fixa / Tesouro✅ Editável (campo é "Taxa Contratada %", informada pelo usuário)
Ativo personalizado✅ Editável (sem fonte de preço automática)
API falhou / sem preço✅ Editável (fallback manual)

3. Categoria "Tesouro Direto" removida

A categoria foi retirada da etapa 1 do modal. Posições de Tesouro existentes na carteira continuam aparecendo normalmente porque eram salvas com class: 'renda_fixa' via mapeamento CATEGORY_TO_CLASS.tesouro = 'renda_fixa'. A remoção é apenas do ponto de entrada para novas adições.

Limpeza de código morto associada:

  • Entrada tesouro em CATEGORIES (com ícone Landmark)
  • Lista de 14 títulos pré-cadastrados em ASSETS_BY_CATEGORY.tesouro
  • Mapeamento CATEGORY_TO_CLASS.tesouro
  • Variável isFixedIncome simplificada — deixou de checar 'tesouro'
  • Import não utilizado Landmark removido
Grid resultante: 5 categorias (Renda Fixa, Renda Variável, Fundos Imobiliários, Internacional, Criptomoedas) — antes eram 6.

🌗 Tema — Detecção Automática do SO

O que mudou

  • Botão "Sistema" removido da seção Aparência em /configuracoes — grid passou de 3 para 2 colunas
  • Quando o usuário ainda não escolheu manualmente Claro ou Escuro, o app passa a seguir automaticamente o tema do sistema operacional
  • Acompanha mudanças do SO em tempo real via matchMedia('change')
  • Escolha manual sempre vence: ao clicar em Claro ou Escuro, o valor fica salvo no localStorage e a detecção do SO é desligada

ThemeContext.tsx — lógica nova

useEffect(() => {
  const saved = localStorage.getItem('nuvary_theme') as Theme | null;
  const systemPrefersDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
  const initial: Theme = saved ?? (systemPrefersDark ? 'dark' : 'light');
  setThemeState(initial);
  applyTheme(initial);

  // Se o usuário ainda não escolheu, acompanha mudanças do SO em tempo real
  if (!saved) {
    const mq = window.matchMedia('(prefers-color-scheme: dark)');
    const handler = (e: MediaQueryListEvent) => {
      const next: Theme = e.matches ? 'dark' : 'light';
      setThemeState(next);
      applyTheme(next);
    };
    mq.addEventListener('change', handler);
    return () => mq.removeEventListener('change', handler);
  }
}, []);

📸 Avatar no Header

O círculo do usuário no canto superior direito (em DashboardLayout.tsx e Header.tsx) sempre exibia apenas a inicial do nome (profile?.nome?.charAt(0)). Mesmo após o upload em /perfil, a foto não aparecia no header.

Correção

Os componentes agora leem profile?.avatar_url do AuthContext e renderizam a imagem quando disponível, mantendo a inicial como fallback.

<div className="w-9 h-9 ... overflow-hidden">
  {profile?.avatar_url ? (
    <img
      src={profile.avatar_url}
      alt="Foto de perfil"
      className="w-full h-full object-cover"
    />
  ) : (
    <span className="text-white font-semibold text-sm">
      {profile?.nome?.charAt(0).toUpperCase() || user?.email?.charAt(0).toUpperCase() || 'U'}
    </span>
  )}
</div>

O AuthContext.refreshProfile() já era chamado dentro de handleFotoChange() em perfil/page.tsx após o upload — então a foto aparece no header imediatamente, sem precisar recarregar a página.

Por que <img> e não Next <Image>? A URL vem do Supabase Storage (domínio externo) e usar <Image> exigiria configurar remotePatterns no next.config.ts. Para um avatar de 36px, a otimização do Next não traz ganho real.

🪣 Bucket "avatars" no Supabase Storage

O upload do avatar (em authService.uploadAvatar()) escreve em storage.objects do Supabase. Antes, isso falhava silenciosamente porque o bucket nem existia. Foi criado um SQL idempotente em sql/avatars_storage.sql que:

  1. Cria o bucket avatars público (necessário para getPublicUrl)
  2. Define 4 policies de Storage (SELECT, INSERT, UPDATE, DELETE)
  3. Cada usuário só pode escrever em uma pasta <auth.uid()>/ dentro do bucket
  4. Leitura pública (qualquer pessoa pode visualizar avatares)

Policies — padrão de path

-- Path esperado pelo app: "<auth.uid()>/avatar.<ext>"
CREATE POLICY "avatars_insert_own"
  ON storage.objects FOR INSERT
  TO authenticated
  WITH CHECK (
    bucket_id = 'avatars'
    AND (storage.foldername(name))[1] = auth.uid()::text
  );

Mensagens de erro melhoradas em /perfil

O handleFotoChange() agora identifica o tipo do erro do Supabase e mostra mensagem específica em vez de genérica:

Erro originalMensagem exibida
"bucket not found" / "does not exist"Bucket "avatars" não existe — rode sql/avatars_storage.sql
"row-level security" / "policy"Sem permissão — rode sql/avatars_storage.sql
OutrosMensagem real do Supabase (não mais mascarada)

⚙️ /configuracoes — Limpeza de Toggles Cosméticos

A página tinha vários toggles que apenas escreviam em localStorage sem nenhum efeito real (nenhum outro componente lia esses valores). Foram removidos:

Toggle removidoPor quê
"Alertas de variação" (em "Por e-mail")Backend não tem nenhuma lib de envio (verificado: nem nodemailer/sendgrid/resend instalado na época)
"Notícias financeiras" (No dashboard)Flag dashboard_noticias não consumida em lugar nenhum
"Variação do portfólio" (No dashboard)Flag dashboard_variacao idem
"Sugestões do assistente IA" (No dashboard)Flag chat_sugestoes idem

Mantido: "Alertas de variação" da seção topo (toggle verde) — esse de fato está ligado ao Supabase via alertasService e controla o NotificationBell + toasts.

Limpeza arquitetural: com a remoção, o estado preferencias, a chave STORAGE_KEY = 'nuvary_preferencias', a função salvarPreferencias() e o botão "Salvar preferências" (que era o único motivo do estado dual) foram apagados. Os toggles que sobraram (Tema, Alertas de variação, Relatórios semanais) salvam direto na fonte da verdade ao clicar — UX consistente.

"Relatórios semanais" — agora funcional

O único toggle de e-mail que sobrou foi convertido em feature real: persiste em profiles.email_relatorios_ativo e é lido pelo cron semanal do Vercel. Detalhes em doc31.html — Relatório Semanal por E-mail.
